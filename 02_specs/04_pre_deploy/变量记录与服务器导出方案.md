# 变量记录与服务器导出方案

## 2026-08-23 线上质量增补（当前）

- 数据库新增 `ParticipantIntegrityState` 汇总行与 `OnlineIntegrityInterval` 原始区间，离散软提醒/剪贴板摘要/承诺/退出继续使用 `ExperimentEvent`。
- Session 创建时把 Admin 十项线上质量参数写入 `experimentSnapshot.onlineIntegrity`；旧 Session 不随 Admin 修改。
- 每名被试导出新增 `online_integrity.json`；Session 元数据新增团队质量 flags。字段全集和清洗硬规则见 `数据库文件夹手册.md`。
- 剪贴板事件导出显式携带工作段、`taskAssignmentId` 和 `companyId`；平台内复制只保存带 Session 盐的哈希，最近 50 个哈希在当前标签页的 `sessionStorage` 中保留以跨刷新判定，仍不保存原文。
- `hasInvalidInactivity`、`hasOffscreenViolation`、`hasFormalDropout` 任一为真时，当前派生 `sessionDataUsable=false`；单纯掉线恢复只标记。
- A/B 退出必须按非对称业务闭环导出：A 退出终止 B，B 退出不终止 A。

## 2026-07-17 七条件随机化增补

session 成组成功时，正式模式先从当前 `ExperimentRun` 的平衡区组队列原子领取 A0-A8 九条件槽位，再生成角色、公司顺序和运行快照。导出必须同时包含“计划分配”和“实际执行”两层：

- 计划分配：实验局、实验条件、区组及全局位置、分配方法、seed、分配时间。
- 实际执行：AI是否启用及实际请求数、任务级 AI 档位、任务2提醒与到达事件、叙事主题和指导语计划。

A0/A7/A8 的自检要求为：`aiEnabled=false`、`aiCondition=NONE`、AI请求数为0、无图片附件、前后端均无 AI 暴露。A0-A8 必须与 `实验条件与区组随机方案.md` 的固定映射一致。

## 0. 本文目标

本文只解决一件事：正式实验跑完后，我们应该如何保存每个被试、每家公司、每个副线任务和每次 AI 对话的数据，确保后续能回溯原始过程、计算实验变量、导出给研究分析。

本文暂不追求一步到位设计复杂数据仓库。当前目标是先把“实验流程 -> 记录项 -> JSON 结构 -> 变量计算 -> 借鉴变量表”的链条讲清楚。

需要坚持的原则：

1. 先按真实实验流程梳理，不先堆数据库表。
2. 导出结构以 session 为第一层；每个 session 下面固定有两个 participant 目录，A/B 数据分开保存。
3. session 只保存团队共享事实，例如实验配置快照、随机化、公司顺序和共享副线计划；被试作答、事件、AI 聊天、图片附件都必须落到各自 participant 下面。
4. 每个被试的数据要能独立导出和阅读。
5. 结构上接近文件夹树：被试元数据、测试题、练习轮、正式工作段 1/2/3、三次工作段回顾、最终长问卷、任务2、AI 聊天和时间戳。
6. 主线公司数据要按公司拆开，便于之后按公司、按角色、按工作段分析。
7. 副线任务要记录实际抽取了什么、呈现了什么、被试答了什么，以及副线 AI 聊天。
8. AI 上下文不做复杂 prompt 还原，只保存 user-assistant 聊天记录、用时、附件索引和其所属任务位置。
9. 图片附件不直接塞进 JSON；服务器保存图片文件，JSON 里保存图片索引和相对路径。

## 1. 第一步：按实验流程拆解记录边界

本节只梳理流程，先不讨论数据库字段。参与者前台统一使用 `A/B` 和 `任务1/任务2`；内部数据、变量名和导出结构可以继续保留 `A/B`、`mainline`、`sideTask` 等计算字段。

### 1.1 总流程

当前实验主流程：

```text
登录
  -> 等待室 / 自动配对
  -> 开篇指导语第 1 页
  -> 任务表只读预览第 2 页（至少 30 秒）
  -> 同步准备页 1
  -> 测试题
  -> 练习轮工作台
  -> 同步准备页 2
  -> 第 1 段前指导语
  -> 正式工作段 1
  -> 第 1 段工作回顾 / 休息
  -> 第 2 段前指导语
  -> 正式工作段 2
  -> 第 2 段工作回顾 / 休息
  -> 第 3 段前指导语
  -> 正式工作段 3
  -> 第 3 段工作回顾
  -> V3.0 最终长问卷
  -> 独立支付确认
  -> 实验完成页
```

### 1.2 登录、配对、角色随机

流程细节：

1. 被试输入手机号登录。
2. 第一位被试进入等待室。
3. 第二位被试进入后，两人先成组。
4. 正式模式在配对事务内从活动实验局原子领取一个 A0-A8 九条件槽位。
5. 系统使用独立 seed 随机分配内部角色 `A/B`。
6. 前台只显示 `A/B`，不显示实验条件编号或旧职业角色名。
7. session 创建时生成实验条件、角色、公司顺序、任务2和指导语计划快照。

这里要明确两点：

- 成组顺序不是角色顺序。
- 实验条件、角色和公司顺序使用相互独立的 seed，并且都必须能回溯。

### 1.3 开篇指导语、任务表预览与同步准备页 1

流程细节：

1. 两位被试分别阅读固定排版的开篇指导语第 1 页。
2. 第 1 页按“通用指导语 → 任务1 → 任务2与报酬 → 角色说明 → 知情同意”展示，不显示 A0-A8 条件名称。
3. 被试进入第 2 页，只读预览当前 A/B 角色任务表至少 30 秒；该页不写草稿、不进入变量导出。
4. 被试完成第 2 页后进入同步准备页 1。
5. 双方都 ready 后才进入测试题。

这里需要记录指导语与任务表预览完成、ready 时间，但不把实验处理标签暴露给参与者。

### 1.4 测试题

流程细节：

1. 双方各自作答测试题。
2. 系统记录答案、正确数、是否通过。
3. 双方都通过后进入练习轮。

测试题不是正式实验结果，但关系到被试是否理解规则，必须保存。

### 1.5 练习轮

流程细节：

1. 练习轮复用正式工作台结构。
2. 练习轮使用最终测试轮公司 `P37`。
3. 练习轮有任务1答题区、材料区、任务2教学入口；AI 是否出现从测试轮起遵循 A0-A8 条件，A0/A7/A8 无 AI。
4. 练习轮内完成教学引导。
5. 完成练习后，进入同步准备页 2。

当前口径：练习轮真实任务2数量固定为 0，后端不为 `segmentIndex = 0` 创建或返回真实 `SideTaskPlan`。任务2教学需要点击题目时，由前端在任务2面板内临时显示 `practice_demo_sidetask` 演示题；它只用于完成教学步骤，不进入正式任务2计划、作答正确率或反应时变量。

练习轮数据要和正式轮分开。它通常不进入论文主分析，但能用于排查被试是否熟悉系统、是否有异常学习成本。

### 1.6 正式工作段结构

正式阶段共有三个工作段、三次段前指导语、三次工作段回顾和两个休息段：

```text
段前指导语 1 -> 工作段 1 -> 工作段回顾 1 / 休息
-> 段前指导语 2 -> 工作段 2 -> 工作段回顾 2 / 休息
-> 段前指导语 3 -> 工作段 3 -> 工作段回顾 3 -> 最终长问卷 -> 支付确认
```

每个工作段内同时发生：

- A 按共享公司顺序处理公司。
- B 基于公司池动态分配处理公司。
- 任务2按 session 计划释放和提醒。
- 任务1 AI 和任务2 AI 可被使用。
- 工作段结束时，未完成内容需要冻结快照。

### 1.7 A 的任务1

流程细节：

1. A 按 session 共享 formal 公司顺序逐家公司处理。
2. 每家公司有固定 5 分钟窗口。
3. 5 分钟内不能提前提交。
4. 5 分钟到点系统自动提交。
5. 自动提交后，A 信息进入 B 的待开放状态；B 仍需满足自己的 5 分钟窗口。
6. 如果工作段先结束，则冻结当前公司内容，下个工作段继续。

对每家公司都要记录：

- 这家公司是谁。
- 什么时候开始。
- 什么时候 5 分钟到点。
- 当时 AI 是基础版还是升级版。
- 答题区完整内容。
- 自动提交时的内容。
- 冻结和恢复快照。

### 1.8 B 的任务1

流程细节：

1. B 不机械跟随 A 的固定公司顺序。
2. B 从共享 formal 公司池中动态分配公司。
3. 优先从“`A 已提交 && B 未完成 && B 未分配`”的锁定池中抽取。
4. 如果锁定池为空，则 fallback 到 A 当前正在处理的 PreA 公司。
5. 如果二者都没有，B 进入空窗。
6. B 每获得一家新公司就写入 `bCanSubmitAt = assignedAt + 5 分钟`。
7. 开放前，B 可以看自己的材料、写草稿，并仅在 A1-A6 条件下使用 AI；A0/A7/A8 无 AI。
8. 只有 `A 已提交 && bCanSubmitAt <= now` 后，B 才能查看 A 信息、解锁 A 原始材料和提交。
9. `company_metadata.json.timing.bCanSubmitAt` 直接导出数据库原值，用于审计五分钟门禁和计算 B 开放后查看/提交延迟。
9. 是否点击“查看 A 信息”是行为变量，但不是提交门槛。

对每家公司都要记录：

- B 拿到这家公司时属于锁定池还是 PreA。
- 拿到时 A 是否已经提交。
- A 信息何时开放。
- 是否查看 A 信息、何时查看。
- B 自己的答题区完整内容。
- B 反馈区完整内容。
- B pre-A / post-A 阶段 AI 状态。
- 如果跨 AI 升级边界，需要记录。

### 1.9 工作段回顾、最终问卷与支付确认

流程细节：

1. 工作段 1/2/3 结束后分别进入第 1/2/3 段工作回顾。
2. 第 1、2 段进入回顾/休息时冻结任务1内容；提交后等待休息结束和下一段指导语。
3. 第 3 段工作回顾提交后进入最终长问卷。
4. 最终问卷提交后进入独立支付确认，只展示脱敏手机号。
5. 支付确认后记录 `payment_phone_confirmed` 并进入完成页。

三段工作回顾与最终长问卷都按被试保存模板版本、实际显示题目、跳题上下文、答案、提交时间和是否缺失。完整手机号不写入问卷答案或分析导出。

### 1.10 副线任务

流程细节：

1. session 创建时，系统按 A0-A8 条件快照生成任务2配置和计划。
2. 每个正式工作段计划 40 道副线任务。
3. 练习轮不生成真实副线任务；教学演示题只存在于前端，不写入 `SideTaskPlan`。
4. continuous / batch 只操纵提醒频率，不改变后台题目实际到达节奏。
5. 叙事组决定副线题池和主题顺序。
6. 被试看到副线入口后，可以打开副线页作答。
7. 副线有独立 AI 聊天上下文。

当前副线计划不在工作段之间继承：

- 工作段 1、2、3 各自有独立的 40 道计划题。
- 每段开始时给该段计划题打上 `scheduledAt`。
- 段末未作答的副线题标记为归档，不滚入下一工作段。
- 下一工作段使用自己的新计划题和当前段主题。
- 副线 AI 聊天也建议按工作段或题目记录，不默认跨段继承。

当前实现里的 `SideTaskPlan` 是 session 级计划，不是每个被试各生成一套题。导出时可以把同一套计划复制到 A/B 各自目录下，但复制的只是“题目释放计划”；曝光、打开、作答、AI 聊天必须分别挂到各自 participant 目录。若正式实验要求 A/B 对同一道副线题都能独立作答，后续实现必须确保作答去重范围是 `participantId + sideTaskPlanId`，而不是只按 `sideTaskPlanId` 去重。

练习轮教学演示题不进入 `side_plan.json` 或 `side_responses.jsonl`。它最多作为 `ExperimentEvent` / 时间戳事件中的教学行为出现，payload 可带 `source = practice_demo_sidetask`；分析任务2正确率、反应时、释放/提醒节奏时应排除这类演示事件。

这里最重要的是：不能只记录被试答了什么，还要记录系统实际抽取了什么、按什么顺序呈现、哪些题释放了但没答。

正式题量与条件口径：

- 练习轮：真实任务2题数固定为 0；教学演示题仅为前端临时 `practice_demo_sidetask`，不进入 `SideTaskPlan`、正确率、反应时或释放/提醒节奏变量。
- 正式段：每段 40 道，3 段合计 120 道计划题。
- A0/A1/A2/A3/A6/A7：`neutral_info`，每段 40 道中性题；段前 N1/N2/N3 各一次且按团队随机排序。
- A4/A5/A8：`coop_narrative`，每段 20 道当前合作主题题 + 20 道中性题，并按 session 的 C/V/S 主题顺序对应三个工作段；合作 20 题按当前主题的 5 个 subtype 各抽 4 题。
- A0/A1/A2/A4/A5/A8 为 continuous；A3/A6/A7 为 batch。两类条件后台题目都按 session 保存的统一到达参数进入队列，区别只在提醒频率。

当前默认正式工作段是 20 分钟，不是 5 分钟；5 分钟规则分别指 A 单家公司窗口和 B 获得每家公司的独立处理窗口。任务2实际到达间隔由 session 创建时保存的 Admin 参数决定，未在工作段内释放或未作答的题按当前段规则归档，不滚入下一段。

### 1.11 AI 区

流程细节：

1. 主线 AI 按公司隔离聊天上下文。
2. 副线 AI 按副线场景或当前副线任务记录聊天。
3. 正式 AI 条件为 NONE / BASIC / ADVANCED；A0/A7/A8 从测试轮起无任务1和任务2 AI。
4. ADVANCED 支持图片上传或粘贴，BASIC 不支持图片。
5. AI 聊天需要保存 user-assistant 每轮对话、创建时间、完成时间或耗时、模型名、AI 档位、附件索引。

图片处理建议：

- 被试上传的图片保存为服务器文件。
- 图片按被试归档到 `attachments/images/`。
- 文件名使用时间戳和短随机后缀，例如 `20260606T153012_482Z_ai_7f3a.png`。
- AI 聊天 JSON 里只保存 `imageRef` 和相对路径，不保存 base64。

## 2. 第二步：按流程推导每一步要记录什么

本节把第一步流程转成记录项。

### 2.1 登录、配对、随机化

记录项：

- 被试 ID、手机号或名单 ID。
- 登录时间、客户端时间。
- session ID、session code。
- 等待室创建时间、加入时间。
- 成组时间。
- 内部角色 `A/B` 与前台角色名。
- 角色随机 seed、方法、时间。
- 实验入口：`manual / formal`。
- 正式实验局、A0-A8 条件、九条件区组号、区组内位置、全局位置、block seed、分配方法和领取时间。
- 实际执行变量：`aiEnabled / aiCondition / segmentAiStates / sideDispatchMode / narrativeGroup / themeOrder / instructionPlan`。
- 公司顺序 seed、正式公司顺序快照。
- 副线抽题 seed、题目计划版本。
- B 动态公司分配的随机策略版本。

### 2.2 指导语与 ready

记录项：

- 指导语版本。
- 展示给该被试的通用块、角色块、实验模式条件块 ID。
- 页面进入时间。
- 点击开始时间。
- ready 阶段：practice ready / formal ready。
- 双方都 ready 的时间。

### 2.3 测试题

记录项：

- 测试题模板 ID、版本。
- 每道题题目 ID。
- 被试选择答案。
- 正确答案。
- 是否正确。
- 总正确数。
- 是否通过。
- 提交时间。
- 如果允许多次作答，记录每次 attempt。

### 2.4 练习轮

记录项：

- 练习轮开始、结束时间。
- 练习公司 ID、材料目录。
- A 练习答题区完整内容。
- B 练习答题区完整内容。
- B 练习反馈区完整内容。
- 教学步骤完成情况。
- 练习轮真实任务2为 0；仅记录前端教学演示题相关教学/时间戳事件。
- 练习轮 AI 聊天记录。
- 练习轮图片附件。

### 2.5 正式工作段

每个工作段记录：

- 工作段编号：1 / 2 / 3。
- segmentIndex：1 / 3 / 5。
- 开始时间、计划结束时间、实际结束时间。
- 当前段 AI 状态。
- 当前段副线模式、叙事组、主题。
- 工作段结束时的冻结快照。
- 进入下一个休息段的时间。

### 2.6 每家公司主线

对每个被试、每家公司记录：

- 公司 ID、公司代号、公司名称、材料版本。
- 该公司在 A 顺序中的序号。
- 该公司在 B 处理顺序中的序号，如果适用。
- B 分配路径：locked_pool / preA_fallback / idle_after_empty。
- 如果 B 来自锁定池，记录当时锁定池候选公司列表、池大小、分配 seed、最终选中公司。
- 如果 B 来自 PreA fallback，记录当时 A 正在处理的公司。
- 公司材料索引：
  - 公司 ID 通常足以回查线上材料。
  - 为了防止材料版本变化，导出时仍建议保存材料 ID、材料版本、可见范围和 storage key。
  - 不要求保存本地物理目录。
- A 答题区所有字段。
- B 答题区所有字段。
- B 反馈区所有字段。
- 未填写字段按空值保存，不省略字段。
- A 5 分钟窗口时间。
- A 自动提交时间。
- B 查看 A 信息时间。
- B 最终提交时间。
- 各阶段 AI 状态。
- 该公司主线 AI 聊天记录。
- 该公司图片附件索引。

- requestId。

- messageRole：user / assistant。
- content。
- createdAt。
- completedAt 或 latencyMs。
- aiLevel。
- modelVersion。
- 是否允许图片。
- attachments。
- 所属公司 ID，如果是主线。
- 所属副线任务 ID，如果是副线。

- error 状态，如果失败。

对话组织方式：

- 主线：每个被试、每家公司一份 `ai_chat.jsonl`。

## 3. 第三步：把数据组织成树状 JSON / 文件夹结构

本节是本文最重要的结构方案。

### 3.1 总体导出方式

数据量较大，不建议 admin 直接返回一个超大 JSON。

推荐方式：

1. admin 点击生成导出。
2. 服务器在 `storage/exports/` 下生成一个导出目录。
3. 导出完成后压缩为 zip。
4. admin 下载 zip。
5. 未来上线后，可以把 zip 上传到对象存储，并通过受控链接下载。

### 4.9 原始时间与有效时间

数据库继续只保存正式工作段边界、主副线切换事件、`OnlineIntegrityInterval` 原始区间和 `ParticipantIntegrityState.formalDropoutAt`，不新增时间汇总列，也不修改历史记录。导出服务同时生成两套时间参数：

- 原始墙钟参数：`eligibleWorkMs`、`totalMainTimeMs`、`totalSideTimeMs`、`mainTimeShare`、`sideTimeShare`。这些字段保持原有含义，确保旧分析脚本不被静默改义。
- 有效时间参数：`validEligibleWorkMs`、`validMainTimeMs`、`validSideTimeMs`、`validMainTimeShare`、`validSideTimeShare`。
- 扣除审计参数：`invalidInactivityExcludedMs`、`offscreenViolationExcludedMs`、`invalidBehaviorExcludedMs`、`disconnectExcludedMs`、`postDropoutExcludedMs`、`totalExcludedMs`。

扣除规则：

1. 正式开启的 `INACTIVITY` 区间全部扣除；120 秒无操作计时和随后 20 秒确认期不倒推扣除。
2. `OFFSCREEN` 仅在 `isViolation=true` 时扣除整个切屏区间；不扣短切屏和未超过上限的授权文件选择窗口。
3. `DISCONNECT` 从有效时间中扣除，但继续作为独立技术状态，不自动转成异常行为。
4. 正式退出后至对应工作段结束的时间扣除，避免 B 退出而 A 继续时高估 B 的参与时间。
5. 不同区间发生重叠时先合并为时间并集，只扣一次；主线、副线、逐工作段和逐公司口径使用同一组区间。

上述参数同时进入 `timestamps.json.derived` 和 `variables.json.timing`；`formalWorkSegments`、`sideSwitches`、`companyTimelines` 另保存各自的有效时长与扣除时长，供研究者复核。任何质量 flag 仍照常保存，生成有效时间不代表把异常样本重新判为可用。

## 5. 第五步：师兄变量表的后置项

`D变量表_整理版.md` 中的大部分论文变量都不应该作为数据库实时字段硬塞进去。更优雅的做法是：数据库和导出包保存原始事实，师兄或后处理脚本在实验结束后计算论文变量。

只要前四步的原始数据完整，下面这些内容可以通过后处理得到，不需要提前把数据库做得很臃肿：

- 处理变量：实验局、A0-A8 条件、九条件区组位置、固定映射、seed、AI 状态、提醒模式、叙事与指导语主题顺序。
- 公司流转变量：A/B 公司顺序、锁定池大小、PreA fallback、FlowLag、BPostADuration、SubmittedPerSegment、空窗时间。
- 内容原始变量：A 表单、B 表单、B feedback、解锁前草稿快照、段末冻结快照。
- AI 使用变量：AI 请求次数、基础版/升级版次数、请求耗时、图片次数、主线/副线 AI 使用。
- 副线变量：释放数、打开数、作答数、正确率、反应时、归档数、continuous / batch 暴露差异。
- 问卷变量：测试题、三次工作段回顾、V3.0 最终长问卷的原始题项、实际显示题号、跳题上下文和支付确认状态。

但后处理不能无中生有。下面这些如果未来要算，必须先有对应原始来源；当前不作为第一版数据库核心字段：

- 内容质量分数需要后续评分系统或人工评分表。
- gold fact / gold issue 需要研究者提前维护公司金标准。
- 原始高频 focus/blur、滚动和细粒度停留时间，只有在事件日志真的记录后才能计算；正式 `OFFSCREEN` 区间和剪贴板摘要已落库并导出。
- AI 采纳率需要 AI 聊天、最终文本、复制粘贴或文本相似度/人工编码共同支持。

师兄变量表里还有一批更偏“后处理 / 论文分析 / 评分系统”的内容，当前先不塞进第一版导出树，后面单独加：

- 评分表：`score_record`、rubric、人工评分员、盲评、裁决记录。
- 金标准：gold fact、gold issue、公司标准机会/风险、标准建议。
- 内容质量变量：`A1Correct`、`A2IssueCoverage`、`MemoQuality`、`SourceTransparency` 等。
- 当前已落地的时间变量：原始与有效 `MainTimeShare` / `SideTimeShare`、各类线上质量扣除时长、`SwitchCount`、`RestartDelay`、`ReturnDelayAfterAIResponse` 等；更细的 `MainSpellLength`、滚动和原始高频 focus/blur 仍属后续。
- 复杂行为变量：滚动、复制、粘贴、focus/blur、细粒度停留时长。
- 论文派生变量字典：把原始 JSON/JSONL 转成论文表格变量的计算规则。

当前记录层已经保证原始数据完整、结构稳定、可导出，并已生成 `timestamps.json` 与常用时间变量摘要。评分、金标准和 AI 采纳率仍作为后续“评分与变量计算模块”补充。

## 6. 当前文档结论

更合适的路线不是“先建一堆表”，而是：

1. 先按实验流程确定每一步记录边界。
2. 再按流程列出必须保存的原始数据。
3. 用被试级树状 JSON/JSONL 组织导出。
4. 用 `variables.json` 保存核心处理变量和常用派生摘要。
5. 师兄变量表作为后处理和论文变量字典的参考，不原样照搬进第一版数据库。

只要这套结构落地，后续可以同时满足三件事：

- 实验变量能算出来。
- 原始答题、AI 聊天、副线作答都能回溯。
- 数据量变大后仍然可以通过服务器归档 zip 管理，而不是 admin 页面直接塞一个超大响应。
