# 正式实验前全流程终审（2026-09-06）

> 审查对象：当前 `main` 实现、`APP_FLOW.md`、V0.4 段前指导语/任务2随机化、V3.0 问卷、数据库与导出代码，以及第九次会议《线上实验退出掉线与平台外行为记录_开发规范_V2.0》。
>
> 结论：主流程、九条件随机化、A/B 异步任务、线上质量区间和结构化导出已经形成闭环，可以进入正式测试；但在正式招募前仍必须完成第 7 节的双人手工验收。第九次会议 V2.0 不是当前退出规则和实验条件的最终真源，不能逐条覆盖现实现。

## 1. 最终口径与旧 V2.0 的差异

| 主题 | 当前最终口径 | 第九次会议 V2.0 | 处理 |
|---|---|---|---|
| 条件 | A0-A8 九条件 | A0-A6 七条件 | 以九条件为准 |
| A 退出 | B 立即停止，不再修改/查看/提交 | B 完成当前公司后提前结束 | 以当前口径为准 |
| B 退出 | A 继续完成三个工作段和剩余公司 | A 仅完成当前公司后提前结束 | 以当前口径为准 |
| 提前结束问卷 | 不增加额外短问卷 | 在线者进入短问卷 | 当前明确不做 |
| 全屏 | 正式工作段要求全屏；退出全屏阻断继续 | 明确不开发强制全屏 | 以后续会议决定为准 |
| 切屏 | 全部记录，严格超过 2 秒才标记违规 | 记录统一平台外区间 | 已兼容，并保留 2 秒阈值 |
| 无效行为 | 120 秒无操作提示，20 秒未确认后开启无效区间 | 旧文档未冻结该完整状态机 | 已按最终会议实现 |

因此，V2.0 仅用于核对“最少原始事件、掉线/切屏互斥、剪贴板来源、分析层级”思路，不作为退出分支和参与者文案的覆盖来源。

## 4. 数据库与导出完整性

### 4.1 已能直接导出的核心变量

- Session/团队：A0-A8 条件、处理映射、实验局/区组槽位、角色随机、公司顺序、B 动态派单日志、段前指导语计划与全部 seed。
- 参与者：角色、全部问卷、规则承诺与理解检查、最终线上自报、质量 flags、付款确认状态。
- 公司：A/B 草稿和提交、A 五分钟起止、B 分配/开放/查看/提交时间、材料版本、AI 档位与跨升级边界。
- 任务2：120 条计划、题库版本、工作段/池/主题/subtype、计划/释放/查看/作答/正确性、提醒曝光。
- AI：上下文类型、公司/任务/工作段、请求与响应、等待时间、provider 状态、图片附件元数据。
- 时间：原始工作段/公司/主副线/AI 等待事件，以及扣除无效、违规切屏、掉线、退出后时段的派生有效时间。
- 线上质量：INACTIVITY/OFFSCREEN/DISCONNECT 原始区间、阈值、次数、时长、退出、剪贴板摘要和团队可用性。

### 4.2 本轮补齐

1. `company_metadata.json.timing.bCanSubmitAt` 直接输出数据库原值，不再只能由 `bAssignedAt + 300 秒` 推导。
2. `online_integrity.json.events[]` 显式输出事件 ID、角色、工作段、任务和公司字段。
3. 复制/粘贴事件由服务端验证任务属于当前 Session，并用数据库回填公司，支持个人×段×公司聚合。
4. 平台内复制哈希保留最近 50 个，不因一次新复制或页面刷新立刻失去匹配能力；仍不保存原文。
5. OFFSCREEN 与 DISCONNECT 在掉线边界互斥，避免平台外时间和掉线时间重复累计。

### 4.3 第九次会议“六张分析 CSV”的判断

当前导出不是 V2.0 设想的六张物化 CSV，而是保存审计原始层与平台生成的 JSON 派生层。现有数据足以在服务器导出后按个人、团队、工作段、公司得到大多数 V2.0 指标，且粒度比六张 CSV 更完整；但“拿到压缩包就直接得到六张论文分析表”目前没有做到。

这不是原始数据缺失，而是分析交付形式尚未物化。是否补六张 CSV 应由最终统计分析表字段决定，因为旧 V2.0 的 A0-A6、退出和短问卷口径已经失效。正式数据开始前若师兄坚持六张固定表，应先冻结 A0-A8 最终字段字典，再单独实现服务器端聚合导出，不能直接照旧 Word 开发。

### 4.4 无法从普通网页可靠得到的变量

- 另一个显示器/手机/另一台电脑是否使用 AI。
- 失焦后具体打开了微信、浏览器、桌面还是其他软件。
- 剪贴板原文及网站外具体来源（出于隐私明确不记录）。
- 用户是否真的注视屏幕；鼠标键盘活动只能作为行为代理。

## 5. 终审发现的剩余风险

### P0：正式招募前必须处理或接受

1. **参与者 API 没有签名身份令牌。** 当前主要以 `sessionCode + participantId/role` 识别参与者；知道这些标识的人理论上可直接调用接口。Admin 已有强认证，但参与者接口尚未做同等级鉴权。实验参与者通常看不到对方 ID，现实风险有限，但公网正式实验建议补短期签名 token 并在所有读写接口校验。此项属于跨前后端协议改造，本轮没有擅自加入。
2. **必须做一次生产环境双人、真实计时的全流程验收。** 单元测试和构建不能替代两个独立浏览器对 30 秒预览、15 秒段前页、A/B 双 5 分钟、三段切换、掉线退出和最终导出的联动验证。

### P1：不阻塞流程测试，但正式数据前应明确

1. 六张固定分析 CSV 尚未物化；当前为可审计 JSON + JSONL + 派生 JSON。
2. 正式工作前单人离场没有自动拆队/重排逻辑，需实验员人工取消或另开 Session。
3. 服务器有容器重启和文件备份流程，但没有 PostgreSQL PITR、自动异地备份和外部错误告警。

### 已在本轮立即收口

- 生产环境 `/dev/*` 预览路由现在返回 404，避免开发预览页被误用或向真实 Session 写进度。
- B 开放时间、剪贴板上下文、跨刷新哈希、切屏/掉线互斥已修复并加入自动测试。

## 7. 正式测试手工清单

必须使用两个真正独立的浏览器上下文分别登录 A/B，并在最终一次测试中保留导出包：

1. 九个 Session 连续配对，确认一个区组恰好覆盖 A0-A8，暂停/恢复实验局不会重置槽位。
2. A/B 指导语逐字核对；任务表预览按钮 30 秒前不可用；双方准备与测试题屏障不会单边越过。
3. 三段段前文本各出现一次、15 秒门禁有效；合作条件 C/V/S 和中性条件 N1/N2/N3 顺序与导出 seed 一致。
4. A 第一家公司自动提交；B 即使先拿到已提交公司也必须从自己的分配时刻再等满 5 分钟；检查 `bCanSubmitAt` 导出值。
5. B 在 PreA 状态不能看 A 信息/材料或提交；A 提交且 B 满 5 分钟后才同时开放。
6. 任务2 continuous 每题提醒、batch 聚合提醒，但两组题目到达时刻一致；合作段检查 5 个 subtype 各 4 题。
7. 切出微信/Win+D 1 秒和 3 秒各一次；确认两次都落区间，只有 3 秒为违规，返回后必须恢复全屏。
8. 打开图片选择框 30 秒不违规；超过 Admin 上限后应违规。
9. 触发 120 秒提示并在 20 秒内确认；再触发一次不确认，确认 `hasInvalidInactivity=true` 且 Session 不可用。
10. 断网后在退出阈值前恢复，确认原公司/草稿恢复且只有 DISCONNECT；在切屏状态断网，确认区间不重叠。
11. A 退出：B 立即看到“队友 A 已退出，实验结束”，并验证前端按钮和直接 API 都不能继续提交。
12. B 退出：A 收到提示后仍能继续后续公司、三段问卷、最终问卷和付款确认。
13. 从实验页复制两段文字、刷新后分别粘贴，均应为 internal；从微信复制后粘贴应为 external，并检查工作段/任务/公司字段。
14. 最终导出逐一检查 `randomization.json`、双方 `variables.json/timestamps.json/online_integrity.json`、三段问卷、每家公司 metadata/answer/AI、任务2 plan/response/exposure 和动态自检文件。
15. 用一局故意违规样本和一局干净样本核对 `sessionDataUsable`；确认原始区间仍保留，派生有效时间只扣区间并不覆盖原始时长。

## 8. 放行标准

第 7 节 15 项全部通过、导出包可解压且动态自检无缺失后，主流程可放行正式实验。若六张 CSV 是师兄的硬性交付物，或参与者 API 鉴权被列为正式上线硬要求，则先完成对应 P0/P1 再放行；否则当前结构已足以开展正式测试和后续清洗脚本开发。
